## 1. Executive Summary & Current State Audit

The **EVRaid Fleet Platform Web Dashboard (`frontend`)** is the primary multi-tenant web interface for light-mobility operators (e.g., Rabbit Mobility, Loop, golf-cart operators) and EVRaid support/R&D engineers. It consumes normalized telemetry, physics-based diagnostics (`SOC`, `SOH`, `EFC`, cell imbalance, health grades `A/B/C/D`), safety alerts, and warranty evidence generated by the `backend` ingestion pipeline (fed by both the `EvRaid-App` BLE batch uploader and 4G/LTE-M telematics modules).

## 2. Tech Stack & Design System Specification

Per **Master Technical Plan §5.1** and the 5 management reference mockups:

| Layer | Technology Choice | Rationale & Alignment |
|---|---|---|
| **Framework** | **Next.js 14+ (App Router)** with TypeScript | Server Components + Client interactivity, clean route grouping for Tenant Portal vs. EVRaid Admin Console, built-in middleware for RBAC and locale routing. |
| **Styling & UI Primitives** | **Tailwind CSS** + **shadcn/ui** (Radix UI) + **Lucide Icons** | Matches the clean enterprise visual language in Mockups #1–#5 (soft slate borders `#E2E8F0`, white cards on `#F8FAFC` canvas, pill badges, accessible drawers/modals). |
| **State & Real-Time Polling** | **TanStack Query (React Query v5)** | Automatic 15–30s polling/revalidation to keep pack telemetry latency $< 60\text{ s}$ (p95 KPI), optimistic updates for alert acknowledgement and work-order drag/drop. |
| **Charts & Visualizations** | **Recharts** | Responsive SVG charts for the **Cell Voltages Bar Chart** (with custom cell color highlighting `weakest_cell_index`), **12-Month Average SOH Line Chart**, and **SOH Linear Fade Projection Chart** with dashed 80% threshold line. |
| **Geospatial Map** | **Mapbox GL JS** (`react-map-gl`) or **MapLibre GL** | High-performance marker clustering for 1,000–100,000 packs, custom status/grade pins, geofence polygon overlays (`FR-3.7`), and location trail polylines. |
| **Internationalization (i18n)** | **`next-intl`** (`en` P0, `ar` P1) + Tailwind logical properties (`ms-*`, `me-*`, `ps-*`, `pe-*`) | Native switching between English (`dir="ltr"`) and Arabic (`dir="rtl"`) without breaking sidebar, table, or chart layouts. |
| **Reports & Exports** | **`@react-pdf/renderer`** (or server PDF endpoint) + **PapaParse** | Monthly Fleet Health PDF report and CSV exports for packs, alerts, and R&D datasets (`FR-4`, `FR-6`). |

## 5. Required Backend API Additions to Power the Frontend

Currently, `backend/app/api/v1/endpoints/` implements:
* `POST /api/v1/telemetry/batch` (`telemetry.py`)
* `POST /api/v1/integrations/warranty/sync-pack` (`warranty.py`)
* `GET /api/v1/packs/{pack_serial}/live` (`packs.py`)

To connect every screen in `frontend/` to real backend state, add the following REST endpoints in `backend/app/api/v1/endpoints/`:

| Endpoint | Method | Purpose / Frontend Consumer |
|---|---|---|
| `/api/v1/fleets/{fleet_id}/overview` | `GET` | Aggregates the 5 Overview KPIs, Health Grade distribution (`A–D`), 12-month SOH trend, top critical alerts, and lowest-SOH packs for **Screen 1**. |
| `/api/v1/packs` | `GET` | Paginated, searchable (`q=serial/imei/ble_name`), sortable (`sort_by=soh_pct|soc_pct|efc|last_seen`), filterable list of packs + map coordinates for **Screens 2 & 3A**. |
| `/api/v1/packs` | `POST` | Register a new pack by serial/QR and assign to customer & fleet (`FR-5`). |
| `/api/v1/packs/{serial}/history` | `GET` | Returns SOH history + linear fade projection (`FR-2.6`), Usage Profile (`FR-2.7`), Location History trail, and paginated Raw Telemetry (`raw_payload`) for **Screen 3B tabs**. |
| `/api/v1/packs/{serial}/diagnostics/run` | `POST` | **"Run diagnostic"** button action: recalculates physics diagnostics and health grade on latest stored telemetry (`Checklist M4 line 161`). |
| `/api/v1/alerts` | `GET` | Filterable list of alerts (`status`, `severity`, `assigned_to`) for **Screen 4**. |
| `/api/v1/alerts/{alert_id}/acknowledge` | `POST` | Marks alert `Acknowledged`, records `acknowledged_at` and user ID in `audit_log` (`FR-3`, `FR-6`). |
| `/api/v1/alerts/{alert_id}/assign` | `POST` | Assigns alert and optionally creates a linked manual **Work Order** (`TO DO` / `IN PROGRESS` / `WAITING ON EVRAID` / `DONE`). |
| `/api/v1/devices/modules` | `GET` / `POST` | Lists device registry (`IMEI`, `ICCID`, network, RSSI, BMS FW) and links/swaps a module on a pack (`FR-5`, **Screen 6**). |
| `/api/v1/reports/monthly` | `GET` | Generates monthly fleet health summary data / CSV stream (`FR-4`). |
| `/api/v1/admin/mappings` | `GET` / `PUT` | EVRaid Super-Admin CRUD for `bms_firmware_profiles` (`cell_channel_map`) and `telemetry_field_mappings` (Master Plan §3.3). |
